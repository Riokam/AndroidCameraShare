# CameraShare (AndroidCameraShare)

Приложение для Android: телефон в комнате работает как видео-няня. В дежурстве слушает HTTP в локальной сети, камера выключена. Картинка идёт по WebRTC только когда зритель открыл страницу в браузере и ввёл PIN.

Текущая версия: **1.3.1** (Android `versionCode` **17**).

## Возможности

- Дежурный режим в фоне (foreground-сервис, тихое уведомление)
- Фирменная иконка CameraShare и согласованный экран запуска
- Адрес в LAN и QR-код на главном экране
- Просмотр с компьютера или телефона в той же Wi‑Fi сети: страница в браузере, PIN из 4 цифр
- Адаптивные страницы ввода PIN и просмотра для Windows, Android и iOS; PIN отправляется после четвёртой цифры, кнопкой или Enter
- Камера включается только на время просмотра (640×360, 15 кадр/с)
- Видео на весь кадр; статус и заряд сверху полупрозрачно
- Кнопки плеера поверх картинки: стоп (квадрат), смотреть (треугольник), поворот 180°, смена камеры, полный экран
- На телефоне кнопки скрыты во время просмотра — нажатие на кадр показывает или прячет их; на ПК они всегда внизу
- Зритель автоматически переподключается после краткого разрыва или возврата из фона
- Страница запрашивает Screen Wake Lock на время просмотра и предупреждает, если браузер не разрешает API в текущем HTTP-режиме
- Основная камера сразу повёрнута на 180°; иконка поворота отменяет или возвращает
- «Остановить просмотр» гасит только камеру; **дежурный HTTP остаётся**
- Смена основной / фронтальной камеры во время просмотра — с няни или кнопкой камеры у зрителя
- «Проверить камеру» на телефоне, чтобы увидеть, что попадает в кадр
- Уровень заряда телефона на странице зрителя
- Автозапуск после перезагрузки (включается в настройках)
- Светлая, тёмная или системная тема интерфейса
- Портретная и горизонтальная ориентации приложения
- Режим питания: экономия или надёжный приём; опция снижать яркость окна и разрешать обычное гашение экрана при просмотре
- Один зритель: второе устройство получает сообщение, что камера занята

## Как пользоваться

1. Соберите и установите приложение на Android-телефон (minSdk 26, targetSdk 35).
2. В настройках задайте PIN (4 цифры) и при необходимости порт (по умолчанию 8080).
3. Включите **дежурный режим**. Телефон и зритель должны быть в одной Wi‑Fi сети (без изоляции клиентов на роутере).
4. Отсканируйте QR или откройте URL вида `http://192.168.x.x:8080` в браузере.
5. Введите PIN. Видео на весь экран, сверху статус и заряд. На телефоне нажмите на картинку, чтобы показать кнопки плеера. После стопа на няне статус **«Ждёт запрос»**, не «Выключено».

При установке поверх предыдущей APK `ApplicationVersion` (Android `versionCode`) должен быть больше, чем у уже стоящей сборки. Сейчас это **17**.

PIN не попадает в URL, в QR и в логи. Браузер шлёт его заголовком `X-Pin` или cookie.

## Требования

- Windows, [Visual Studio 2022](https://visualstudio.microsoft.com/) с workload **.NET Multi-platform App UI development**
- .NET 10 SDK, MAUI
- Android-устройство с USB-отладкой (или эмулятор)
- Телефон и зритель в одной локальной сети

Fast Deployment на части телефонов (например OnePlus) ломает запуск — в проекте включено `EmbedAssembliesIntoApk`.

## Сборка и тесты

Решение: `AndroidCameraShare/AndroidCameraShare.slnx`.

```text
AndroidCameraShare/
  AndroidCameraShare.slnx          — решение
  Directory.Build.props            — версия приложения
  AndroidCameraShare/              — MAUI, только Android
  AndroidCameraShare.Core/         — HTTP, PIN, страница зрителя (без Android)
  AndroidCameraShare.Tests/        — xUnit
```

В Visual Studio: открыть `.slnx`, выбрать Android-проект, F5 на устройство.

Тесты (логика без камеры и WebRTC):

```powershell
dotnet test AndroidCameraShare/AndroidCameraShare.Tests/AndroidCameraShare.Tests.csproj
```

## HTTP на телефоне

Пока дежурство включено:

| Метод | Путь | PIN | Назначение |
| --- | --- | --- | --- |
| `GET` | `/` | да | Форма PIN или страница просмотра |
| `GET` | `/health` | нет | `duty`, число зрителей, версия |
| `GET` | `/status` | да | Заряд батареи и какая камера (`back` / `front`) |
| `POST` | `/offer` | да | SDP offer → answer и идентификатор сессии; второй зритель получает 409 |
| `POST` | `/hangup` | да + сессия | Остановка своего просмотра: камера гаснет, дежурство не трогаем |
| `POST` | `/camera` | да + сессия | Смена основной / фронтальной камеры активным зрителем |

Неверный PIN даёт 401; повторные попытки с одного IP временно ограничиваются ответом 429. PIN в query-строке не принимается.

## Версии

Одна версия на продукт: Core не нумеруется отдельно.

Номер задаётся в `AndroidCameraShare/Directory.Build.props`:

- `Version` — SemVer для UI и `/health` (patch / minor / major)
- `ApplicationVersion` — Android `versionCode`, только вверх при установке поверх предыдущей APK

При выпуске меняйте только этот файл. В настройках строка вида «Версия 1.3.1 (17)» — `versionName` и `versionCode` установленного APK.

## Безопасность

- Доступ к видео только по PIN в LAN, без облака и без аккаунтов
- PIN хранится в Android Keystore через SecureStorage; старое значение переносится автоматически
- Дежурный режим не запускается, пока корректный PIN не задан
- Камера и CPU lock только на сессию просмотра
- Release-сборка хранит ограниченный журнал с ротацией без PIN и SDP
- Это не замена HTTPS и не защита от того, кто уже в вашей Wi‑Fi сети и знает PIN
- Не публикуйте PIN, не кладите его в QR и не коммитьте ключи подписи
