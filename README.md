# Няня (AndroidCameraShare)

Приложение для Android: телефон в комнате работает как видео-няня. В дежурстве слушает HTTP в локальной сети, камера выключена. Картинка идёт по WebRTC только когда зритель открыл страницу в браузере и ввёл PIN.

Текущая версия: **1.1.3**.

## Возможности

- Дежурный режим в фоне (foreground-сервис, тихое уведомление)
- Адрес в LAN и QR-код на главном экране
- Просмотр с компьютера или телефона в той же Wi‑Fi сети: страница в браузере, PIN из 4 цифр
- Камера включается только на время просмотра (640×360, 15 кадр/с); основная камера у зрителя горизонтальная
- На странице зрителя видео вписывается в окно, кнопки всегда внизу без прокрутки
- «Остановить просмотр» сразу гасит камеру; **дежурный HTTP остаётся**
- Смена основной / фронтальной камеры во время просмотра — картинка у зрителя меняется сразу
- «Проверить камеру» на телефоне, чтобы увидеть, что попадает в кадр
- Уровень заряда телефона на странице зрителя
- Автозапуск после перезагрузки (включается в настройках)
- Режим питания: экономия или надёжный приём; опция гасить экран няни во время просмотра
- Один зритель: новый просмотр заменяет предыдущий

## Как пользоваться

1. Соберите и установите приложение на Android-телефон (minSdk 26, targetSdk 35).
2. В настройках задайте PIN (4 цифры) и при необходимости порт (по умолчанию 8080).
3. Включите **дежурный режим**. Телефон и зритель должны быть в одной Wi‑Fi сети (без изоляции клиентов на роутере).
4. Отсканируйте QR или откройте URL вида `http://192.168.x.x:8080` в браузере.
5. Введите PIN. Должно появиться видео, заряд и кнопки «Остановить просмотр» / «Смотреть». После стопа на телефоне статус **«Ждёт запрос»**, не «Выключено».

При установке поверх предыдущей APK `ApplicationVersion` (Android `versionCode`) должен быть больше, чем у уже стоящей сборки. Сейчас это **5**.

PIN не попадает в URL, в QR и в логи. Браузер шлёт его заголовком `X-Pin` или cookie.

## Требования

- Windows, [Visual Studio 2022](https://visualstudio.microsoft.com/) с workload **.NET Multi-platform App UI development**
- .NET 10 SDK, MAUI
- Android-устройство с USB-отладкой (или эмулятор)
- Телефон и зритель в одной локальной сети

Fast Deployment на части телефонов (например OnePlus) ломает запуск — в проекте включено `EmbedAssembliesIntoApk`.

## Сборка и тесты

Решение: `AndroidCameraShare/AndroidCameraShare.slnx`.

```text
AndroidCameraShare/
  AndroidCameraShare.slnx          — решение
  Directory.Build.props            — версия приложения
  AndroidCameraShare/              — MAUI, только Android
  AndroidCameraShare.Core/         — HTTP, PIN, страница зрителя (без Android)
  AndroidCameraShare.Tests/        — xUnit
```

В Visual Studio: открыть `.slnx`, выбрать Android-проект, F5 на устройство.

Тесты (логика без камеры и WebRTC):

```powershell
dotnet test AndroidCameraShare/AndroidCameraShare.Tests/AndroidCameraShare.Tests.csproj
```

## HTTP на телефоне

Пока дежурство включено:

| Метод | Путь | PIN | Назначение |
| --- | --- | --- | --- |
| `GET` | `/` | да | Форма PIN или страница просмотра |
| `GET` | `/health` | нет | `duty`, число зрителей, версия |
| `GET` | `/status` | да | Заряд батареи и какая камера (`back` / `front`) |
| `POST` | `/offer` | да | SDP offer → answer, включение камеры |
| `POST` | `/hangup` | да | Остановка просмотра: камера гаснет, дежурство не трогаем |

Неверный PIN даёт 401 с короткой задержкой. PIN в query-строке не принимается.

## Версии

Номер задаётся в `AndroidCameraShare/Directory.Build.props`:

- `Version` — SemVer для UI и `/health` (patch / minor / major)
- `ApplicationVersion` — Android `versionCode`, только вверх при установке поверх предыдущей APK

При выпуске меняйте только этот файл. В настройках приложения строка «Версия …» берётся оттуда же.

## Безопасность

- Доступ к видео только по PIN в LAN, без облака и без аккаунтов
- Камера и CPU lock только на сессию просмотра
- Это не замена HTTPS и не защита от того, кто уже в вашей Wi‑Fi сети и знает PIN
- Не публикуйте PIN, не кладите его в QR и не коммитьте ключи подписи
